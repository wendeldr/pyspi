# Paths and how to run things

This is a short map of where the audit's pieces live and how to re-run them. `README.md` explains how to read the CSV and the
score columns. `HANDOFF.md` gives the stage history.

Every check here compares pyspi's output with another implementation, an analytic case or an external package, within a stated
tolerance. Agreement means the two computations match on the audited data; it is not a proof that either is mathematically right.
The regression goldens are snapshots of current output and are not used as a reference.

It holds, under their scratch-relative paths, the scripts (.py .R .m .sh up to 150 KB) of every scratch directory that records, notes, the reference scripts `checks/refs/*.py` or any other `audit/**/*.py` mentioning the scratchpad cite by path, plus every scratch directory named after a family; the manifest lists path, bytes and sha256. ### Using the comparison venv

The venv's `bin/python` is a symlink to `/usr/bin/python3.12`, so it kept working after the move (checked: NumPy 2.5.4 and SciPy
1.18.1 import, `_kernels_distance.py --selftest` 43/43, `run_checks.py --family xcorr --skip-pyspi` runs). Its console scripts
(`f2py`, `numba`, `mne` and so on) have `#!/tmp/...` shebangs and no longer run. The venv has no pip
(`<scratch>/audit-venv/bin/python -m pip` fails with "No module named pip"), so install into it with uv
(`uv pip install --python <scratch>/audit-venv/bin/python ...`) or rebuild it:

```
uv venv --python 3.12 <new-venv>
uv pip install --python <new-venv>/bin/python -r audit/env/comparison-lock.txt
```

(`uv pip install --dry-run` of the lock file against the current venv reported "Would make no changes" on 2026-10-15.)
Point the check scripts at it without editing any file (`run_checks.py` reads `AUDIT_REF_PYTHON` before
`env/comparison-venv.path`); `run_checks.py` and the selftest line below need the variable set:

```
export AUDIT_REF_PYTHON=~/Documents/pyspi-audit-scratch-2026-10-15/audit-venv/bin/python
```

## How to run and check

Run these from the repo root (`/media/dan/Data/git/pyspi`).

```
# catalogue and records
.venv/bin/python audit/build_units.py --check               # units.yaml matches the live package
.venv/bin/python audit/validate_records.py --stage profiled # every record has every field; score-column invariants

# numeric comparisons (needs the comparison venv; R and Octave for some families)
export AUDIT_REF_PYTHON=~/Documents/pyspi-audit-scratch-2026-10-15/audit-venv/bin/python
export R_LIBS_USER=~/R/audit-lib
.venv/bin/python audit/checks/run_checks.py                 # all families: data -> pyspi -> references -> compare (about 40 min with cached
# pyspi outputs; --force recomputes them and takes longer)
# exit 1 with 'FAILED steps: compare' whenever a comparison fails, which the findings do; a script error shows as a failed
# pyspi_outputs or refs/<family>.py step. Last full run, 2026-10-15: 10609 runs, 9395 pass, 1214 fail, 0 errors (HANDOFF.md)
.venv/bin/python audit/checks/run_checks.py --family xcorr  # one family; --force recomputes, --skip-pyspi reuses pyspi outputs
$AUDIT_REF_PYTHON audit/checks/refs/_kernels_spectral.py --selftest   # likewise _kernels_infotheory, _kernels_distance, _kernels_basic_misc
.venv/bin/python audit/checks/citations.py                  # screens every file:line citation, prints counts per status; --out FILE --only-problems writes the flagged ones

# timing (see README "Optimisation columns"; the exact pass commands are in HANDOFF.md, Next steps 2 and 3)
.venv/bin/python audit/profiles/profile_units.py --summarise --out audit/profiles   # rebuilds profiles/summary.json from the existing records
# --all re-measures every missing (unit, shape, mode) at the default shapes, 118x1024 included, and can run for hours

# deliverables
.venv/bin/python audit/build_csv.py --check                 # exit 1 and "stale: ..." if the CSVs differ from a fresh build
.venv/bin/python audit/build_csv.py                         # rebuilds metrics_audit.csv and identifier_map.csv
.venv/bin/python audit/checks/archive_probes.py --scratch <scratch> --dry-run   # what the probe archive would hold (122 directories, 965 scripts)
```

To check the package itself is untouched: `git status` should show `audit/` plus the user's own files, `uv lock --check` should
be clean, and the default regression tier should pass. The regression tier compares against snapshots of current output.

## Where results are

- Outcome per run: `audit/checks/out/results/<family>.json`, merged into `audit/checks/out/results.json`.
- Verdict and score per unit: the `correctness` block of `records/<unit_id>.yaml`, and the CSV columns `verdict`, `score_0_10` (the original
  score, kept unchanged for provenance), `score_rubric`, `verdict_adjusted`, `score_adjusted` and their reason columns. README section
  "Score columns: original, rubric reading, adjusted" explains them.
- Optimisation avenues: the `optimisation` block of each record, and the opportunity rows of the CSV, ranked by `priority_rank`.
- Readings of the anchor table that reviewers raised but that were deliberately not applied: `_handoff/score_columns_open_readings.md`
  (its last section, `score_columns_followups`, lists the records that later got a pointer sentence). The spec and scripts that filled
  the score columns: `_handoff/score_columns_spec.md` and `_handoff/score_columns_scripts/`.
- What each workflow run returned (agent reports, recheck problems, items left open): `_handoff/*.json`, one file per run; the list
  with one phrase per file is in `HANDOFF.md` under `audit/_handoff/`.
